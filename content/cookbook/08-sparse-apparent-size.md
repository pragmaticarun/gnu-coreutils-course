A sparse file has a logical size larger than the blocks the filesystem has allocated. `truncate -s 1M hole` sets the size to one mebibyte and does not write a mebibyte of zeros. `stat -c 'size=%s blocks=%b'` shows the size and the allocated-block count. On this capture the block count is 0 for a fresh hole. `du -b` is apparent size in bytes, so it prints 1048576. `du -B1` prints the allocation, 0. Both numbers are "the size". A script that alerts on one of them and a human who reads the other will disagree, and both will be quoting the tool correctly.

Copying the file decides whether the hole survives. A naive read of every byte materializes the zeros. `cp --sparse=always` tries to keep holes. A transfer that does not, including some archive tools and some network copies, turns the hole into real blocks and the disk fills. Check `du -B1` after the copy, not only `ls -l`.

`df` will not move by a mebibyte when you create this hole, because the blocks were never allocated. It will move if a later write fills the hole. That is the same distinction the du lesson draws between a tree walk and a filesystem query.

## Steps

```run
# title: Apparent size and allocation
/usr/bin/truncate -s 1M hole
/usr/bin/stat -c 'size=%s blocks=%b' hole
/usr/bin/du -b hole
/usr/bin/du -B1 hole
```

```run
# title: The directory listing shows the logical size
/usr/bin/truncate -s 1M hole
/usr/bin/ls -l hole
```

## Performance

Creating the hole is a metadata update. Reading it back as zeros is a megabyte of generated bytes per mebibyte of logical size, and it will dominate if a backup does it. The fast path is the one that copies extents or skips holes, and it exists only when the filesystem and the tool agree. This host's `cp --reflink=always` fails. Sparseness and reflink are different features. Time the copy you will actually run, on a file large enough to see, and include `du -B1` of the destination in the notes so a materialized hole is visible. The course benchmark does not use a sparse input for the copy trial. It uses an 8 MiB dense file and says so.
