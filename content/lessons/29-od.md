`od` reads bytes and prints them in a chosen representation. It does not modify the file. `-t x1` is hex, one byte at a time. `-t c` is the character view, with escapes for newline and similar. You can stack them: `-tx1c` prints a hex line and a character line. `-An` omits the address column so the dump is easier to compare in a test. `-w2` sets two bytes per line. The default width is wider and wraps in a way that is annoying in a narrow log.

Use `od` when any of these are in doubt: whether a newline is present, whether a UTF-8 character was split, whether a "blank" is a space or a tab or a CR, whether a NUL is in the stream. `cat -A` is a quicker visualization and it is lossy. `od` is the measurement. The fold lesson, the tr lesson, and the tac lesson all end at `od` for that reason.

`od` of a text file you think you understand is also how you learn that the editor added a newline on save. `printf 'abc' > f` followed by `od -An -tx1 f` shows `61 62 63` and nothing else. `printf 'abc\n'` adds `0a`. `wc -l` agrees with the `0a` count and disagrees with the editor's line count when the `0a` is missing. The pair of tools is the habit.

`od` will read a pipe. It has to consume the bytes to show them. It is not a pager. For a huge file, `head -c 64 | od -An -tx1` shows the prefix without dumping the rest. `tail -c` shows the suffix. That combination stays inside coreutils.

## Worked examples

### Hex and characters

```run
# title: od -An -tx1c
/usr/bin/printf 'hi\n' | /usr/bin/od -An -tx1c
```

### A narrow width

```run
# title: Two bytes per line
/usr/bin/printf 'ABCD' | /usr/bin/od -An -tx1 -w2
```

### Named ASCII

```run
# title: od -ta
/usr/bin/printf 'A\n' | /usr/bin/od -An -ta
```

### Missing newline versus present newline

```run
# title: abc versus abc plus newline
/usr/bin/printf 'abc' | /usr/bin/od -An -tx1
/usr/bin/printf 'abc\n' | /usr/bin/od -An -tx1
```

## Recipes

When a golden file test fails and the diff looks empty, dump both files with `od -An -tx1`. A trailing space, a CR, or a missing newline is obvious in hex and invisible in a rendered diff that trims.

When `fold` or `tr` surprises you, dump before and after. Do not argue from the terminal font.

## Tips and pitfalls

The address column changes when the file grows and makes noisy diffs. `-An` is the stable form for tests.

`-t x1z` adds a printable trailer on some versions. Stick to the format letters you have checked in `--help` for 9.4. The examples use `-tx1`, `-tx1c`, and `-ta`.

`od` prints to stdout. A redirect onto the input file truncates it first, like any other tool. Dump to a new file.

## Performance

`od` formats every byte it prints, so the output is larger than the input and the CPU cost is the formatting. Dumping a multi-gigabyte core file to a terminal is the slow operation. Limit the range with `head -c` or `dd count=` first. `od` does not seek to a structure for you; `skip` via `dd` is the offset tool. There is nothing to parallelize in a 16-byte dump. The performance rule is "dump less", not "find a faster od flag".
